Validation — Zenless Steam Bridge 0.2.2

Reported behavior: the manager showed an enabled installation, but starting
Steam ZZZ opened the official launcher without displaying the game cards.

Confirmed implementation gap in 0.2.1:
- Enabling only wrote the synthetic app manifest and copied the frontend.
- Existing per-account LaunchOptions were neither changed nor verified.
- The manager trusted installation.Phase rather than checking launch routing.
The user's exact Steam command before this fix is not available. This build
addresses the routing gap; it does not claim the user's machine was inspected.

Changes:
- Backup the logged-in account's localconfig.vdf and change only ZZZ's
  LaunchOptions to a quoted stable selector EXE followed by literal %command%.
- Do not execute the official launcher command passed as frontend arguments.
- Verify the written launch option, component hashes, marker and app manifest.
- Repair an enabled old version in place, retaining the original uninstall
  backups. Roll back both components and launch settings if repair fails.
- Restore only our launch option, preserving unrelated settings and any launch
  option the user subsequently changes themselves.
- Record frontend entry and export targeted diagnostics, excluding full Steam
  account configuration.
- Set the 96-DPI design baseline, use automatic row sizing and a scrollable
  manager layout.
